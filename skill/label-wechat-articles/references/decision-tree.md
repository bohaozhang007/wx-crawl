# 科技指南与科研项目文章决策树

Tree version: `1.0`

本文件是文章判断节点、终止节点和 `reason_code` 的权威来源。按顺序执行，
在第一个能够确定结论的终止节点停止。不得跳过前置节点，也不得只依赖关键词。

## 目录

- `E1`：文本证据是否足够
- `O1`：是否发布当前可采取行动的机会
- `O2`：申报结构是否完整
- `R1`：机会是否以科研或技术研发任务为核心
- `A1`：确定申请类型
- `T1`：定位任务证据区
- `D1`：任务本身是否匹配目标研究方向
- `K1`：保留
- `*-D*`：排除终点
- `*-R*`：人工复核终点

## 执行规则

1. 依次执行 `E1 → O1 → O2 → R1 → A1 → T1 → D1`。
2. 命中 `*-D*`、`*-R*` 或 `K1` 后立即停止。
3. 多个排除理由同时存在时，以最先命中的终止节点作为 `reason_code`。
4. `reason` 必须解释这篇文章为何命中该节点，不能复制节点名称代替具体说明。
5. `evidence` 必须引用正文中的短证据并标注位置；证据缺失时记录缺失的文件或附件。
6. 只在任务证据区判断技术方向。背景、页脚、作者介绍和相关文章中的词不算任务证据。

## [E1] 文本证据是否足够

### 判断问题

现有文本能否判断文章发布了什么机会、任务是什么，以及任务是否匹配研究方向？

### 通过条件

- `content.txt` 和文本元数据可读，且包含作出判断所需的正文；或
- 虽有附件无法读取，但正文已完整列出申报性质、任务和相关技术方向。

### 分支

- 证据足够 → `O1`
- 正文缺失、损坏或无法读取 → `E1-R1`
- 结论依赖无法读取的关键附件 → `E1-R2`

## [E1-R1] 正文不可用

- Decision: `REVIEW`
- 适用：正文缺失、乱码、截断严重或关键文本文件不可读。
- 不适用：正文可读但内容本身不符合条件；这种情况继续执行后续节点。

## [E1-R2] 缺少关键附件

- Decision: `REVIEW`
- 适用：正文只说“详见附件”，而附件决定任务方向、申报对象或是否属于科研任务。
- 不适用：附件仅提供表格模板、盖章页等，不影响文章性质和方向判断。

## [O1] 是否发布当前可采取行动的机会

### 判断问题

文章的主要目的是否是通知读者现在可以申报、征集、揭榜、提交需求或响应任务？

### 通过条件

- 申报或征集动作是文章当前要读者执行的动作；
- 不是仅仅回忆过去发生过申报，或报道其他主体已经完成的工作；
- 原始链接文章即使截止期后来已过，仍按文章发布时是否构成正式机会判断。

### 分支

- 当前申报、指南、课题征集、需求征集或揭榜机会 → `O2`
- 立项、获奖、入选、评审或拟入选结果 → `O1-D1`
- 新闻报道、工作总结、成果回顾或人物介绍 → `O1-D2`
- 政策发布、规划、解读或信息转发，但没有开放申报 → `O1-D3`
- 会议、论坛、培训、展览、路演或普通活动 → `O1-D4`
- 招聘、招生、人才称号或一般评奖 → `O1-D5`
- 产品发布、融资、技术科普或基础设施消息 → `O1-D6`
- 正文同时包含当前机会和历史结果，无法辨别主动作 → `O1-R1`

## [O1-D1] 结果、公示或名单

- Decision: `DROP`
- 适用：立项结果、拟入选名单、获奖名单、评审结果、公示和结题验收。
- 易误判点：正文可能重复原申报条件，标题或附件仍包含“项目”“指南”“申报”。

## [O1-D2] 新闻、总结或回顾

- Decision: `DROP`
- 适用：会议召开、项目进展、成果发布、领导调研、工作周报和人物事迹。
- 易误判点：新闻可能详细描述一个科研项目，但没有面向读者开放新的申报动作。

## [O1-D3] 政策或信息说明

- Decision: `DROP`
- 适用：政策原文、规划、标准解读、行业分析、办事说明和普通通知。
- 易误判点：政策提出发展方向或未来项目安排，但当前没有可执行的申报入口。

## [O1-D4] 会议、培训或活动

- Decision: `DROP`
- 适用：会议议程、论坛报名、培训通知、展会、沙龙、路演和参观活动。
- 易误判点：活动主题可能与目标技术高度相关，但活动报名不是科研项目申报。

## [O1-D5] 招聘、招生、人才或一般评奖

- Decision: `DROP`
- 适用：岗位招聘、学生招生、人才计划个人申报、荣誉评选和论文奖项。
- 例外：若核心对象是明确的科研课题或技术任务，而非个人资格，继续执行 `O2`。

## [O1-D6] 产品、融资或科普内容

- Decision: `DROP`
- 适用：新品发布、企业融资、技术介绍、研究成果科普和产业新闻。
- 易误判点：文章可能出现大量目标方向术语，但没有任何申报机会。

## [O1-R1] 当前动作不明确

- Decision: `REVIEW`
- 适用：同一正文混合当前征集与历史结果，文本无法确认读者现在能否响应。
- 要求：详细说明冲突的两类证据，不得仅写“内容不清楚”。

## [O2] 申报结构是否完整

### 判断问题

文章是否同时具有申报动作、明确对象和至少一个执行信号？

### 必要结构

1. 申报动作：申报、征集、揭榜、提交课题/需求或同等动作。
2. 明确对象：有名称或具体范围的项目、课题、任务、榜单或技术方向。
3. 执行信号：截止时间、申请资格、材料、附件、提交渠道、联系人、资助周期、
   评审流程中的至少一项。

### 分支

- 三项全部满足 → `R1`
- 缺少真实申报动作 → `O2-D1`
- 缺少明确任务对象 → `O2-D2`
- 缺少任何执行信号 → `O2-D3`
- 文本疑似被截断，无法确认必要结构 → `O2-R1`

## [O2-D1] 没有申报动作

- Decision: `DROP`
- 适用：只说“支持、推进、建设、布局、开展”，没有要求任何主体提交或响应。

## [O2-D2] 没有明确对象

- Decision: `DROP`
- 适用：只出现泛称“项目、课题、创新”，没有名称、任务清单或工作范围。

## [O2-D3] 没有执行信号

- Decision: `DROP`
- 适用：像倡议、预告或宣传口号，读者无法据此采取申报行动。

## [O2-R1] 申报结构疑似缺失

- Decision: `REVIEW`
- 适用：可见部分明显是正式申报通知，但关键段落疑似因抓取截断而缺失。

## [R1] 是否以科研或技术研发任务为核心

### 判断问题

被征集的对象是否要求提出、研究、开发、验证或攻关具体科学技术问题？

### 通过条件

- 有研究内容、技术目标、关键问题、考核指标、原型/系统验证或研发成果要求；
- 企业可申报不构成排除条件，只要被征集对象本身是研发或技术创新任务。

### 分支

- 科研课题、技术攻关、研发指南或创新研发项目 → `A1`
- 一般补贴、资质认定、采购、场景供需或非研发示范 → `R1-D1`
- 普通比赛、创业路演或作品征集，没有研发任务 → `R1-D2`
- 仅征求政策、标准或指南文字意见 → `R1-D3`
- 仅征集产业案例、机构名单或宣传素材 → `R1-D4`
- 任务是否具有研发实质仍无法确定 → `R1-R1`

## [R1-D1] 非研发型机会

- Decision: `DROP`
- 适用：一般资金补贴、企业认定、资格申报、采购供货、场景对接和纯应用推广。
- 例外：若明确要求解决技术问题并形成研发成果、指标或验证系统，继续执行 `A1`。

## [R1-D2] 普通竞赛或路演

- Decision: `DROP`
- 适用：创业比赛、演讲、作品展示、商业计划书评选，没有明确科研任务。
- 例外：竞赛实际采用揭榜攻关形式，并提供具体技术任务和验收指标时继续执行。

## [R1-D3] 意见征集

- Decision: `DROP`
- 适用：对政策、标准、规划或文件草案征求文字意见。
- 例外：征集的是科研项目指南建议，且要求提交具体研究方向或技术任务时继续执行。

## [R1-D4] 案例、名单或素材征集

- Decision: `DROP`
- 适用：优秀案例、解决方案名录、供应商名录、宣传材料和成果展示征集。
- 例外：征集内容包含尚待完成的明确研发任务和技术指标时继续执行。

## [R1-R1] 研发实质不明确

- Decision: `REVIEW`
- 适用：任务兼有市场、采购和研发描述，现有文本不足以判断研发是否为核心交付。

## [A1] 确定申请类型

### 判断规则

- 发布、引用或征集正式 `申报指南`、`项目指南`、`任务指南`、指南方向时，标为
  `科研指南申请`。
- 其他满足前述节点的科研课题、项目、需求或揭榜任务，标为 `科研项目申请`。

### 分支

- 类型确定后 → `T1`

## [T1] 定位任务证据区

### 可以使用的证据

- 项目或课题名称；
- 指南方向、榜单、任务清单；
- 研究内容、关键技术、技术目标；
- 考核指标、验收要求、预期研发成果和交付物。

### 不可使用的证据

- 政策背景、行业综述和发布单位介绍；
- 领导、专家、嘉宾或作者履历；
- 历史成果、往期项目和已完成案例；
- 页脚、导航、广告、相关文章和公众号自动推荐；
- 汇总文章中其他不属于当前申报对象的项目。

### 分支

- 能定位至少一个任务证据区 → `D1`
- 正文声称有任务，但任务完全位于不可读附件中 → `T1-R1`

## [T1-R1] 无法取得任务正文

- Decision: `REVIEW`
- 适用：可确认是科研申报，但所有研究方向和任务内容均在不可读附件或失效链接中。

## [D1] 任务本身是否匹配目标研究方向

### 判断问题

任务证据区是否直接要求研究、开发、验证或交付 `research-profile.yaml` 中的目标方向？

### 通过条件

- 直接术语出现在任务对象、研究内容、技术目标、指标或交付物中；或
- 任务描述与目标方向的专属模式语义等价，且有足够上下文排除同名歧义。

### 分支

- 至少一个方向在任务范围内直接成立 → `K1`
- 方向只出现在背景、机构介绍、履历、历史成果或页脚 → `D1-D1`
- 只出现宽泛词或单独出现的支持词 → `D1-D2`
- 方向只是工具、应用场景或旁支技术，不是任务研究/交付对象 → `D1-D3`
- 任务区不存在任何目标方向 → `D1-D4`
- 任务语义与方向边界确实无法确定 → `D1-R1`

## [D1-D1] 方向仅出现在非任务区域

- Decision: `DROP`
- 适用：目标词只在背景、简介、历史项目、相关文章或其他汇总条目中出现。
- 标签要求：保留已经确定的申请类型，但 `domains` 写 `[]`。

## [D1-D2] 方向证据过宽

- Decision: `DROP`
- 适用：只出现“智能、模型、低空、空间、自动化、机械”等不足以唯一指向目标领域的词。
- 标签要求：保留已经确定的申请类型，但 `domains` 写 `[]`。

## [D1-D3] 方向不是任务对象

- Decision: `DROP`
- 适用：目标技术只是办公工具、宣传手段、通用支撑或可能的应用场景，任务并不研究它。
- 标签要求：保留已经确定的申请类型，但 `domains` 写 `[]`。

## [D1-D4] 任务不属于目标方向

- Decision: `DROP`
- 适用：科研申报结构完整，但研究任务属于其他学科或技术方向。
- 标签要求：保留已经确定的申请类型，但 `domains` 写 `[]`。

## [D1-R1] 方向边界无法确定

- Decision: `REVIEW`
- 适用：任务描述过短或术语有真实歧义，阅读全文后仍不能可靠确定是否匹配。
- 禁止：不得因为不愿作出明确判断而滥用本节点。

## [K1] 满足科研机会与研究方向条件

- Decision: `KEEP`
- 必要条件：`E1`、`O1`、`O2`、`R1`、`A1`、`T1`、`D1` 全部通过。
- 标签要求：申请类型必须为 `科研项目申请` 或 `科研指南申请`，`domains` 至少一项。
- 原因要求：同时解释可申报性、科研任务实质和任务层面的方向匹配。
- 证据要求：至少分别提供一条 `solicitation` 和一条 `domain` 证据。
